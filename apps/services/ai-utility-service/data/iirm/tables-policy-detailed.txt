POLICY-RELATED TABLES DETAILED SCHEMA

CENTRAL LOOKUP TABLE FOR ALL ENUMERATIONS:

lookup_data
   - id: INTEGER, PRIMARY KEY, NOT NULL, auto-increment (lookup_data_id_seq)
   - lookup_key: VARCHAR(255), NOT NULL (categorizes the lookup type)
   - lookup_name: VARCHAR(255), NOT NULL (human-readable category name)
   - value_key: VARCHAR(255), NOT NULL (system key for the value)
   - value: TEXT, NOT NULL (human-readable display value)
   - description: TEXT, NULLABLE (additional details about the lookup value)
   - created_at: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP
   - updated_at: TIMESTAMP, NOT NULL, DEFAULT CURRENT_TIMESTAMP
   - created_by: VARCHAR(255), NOT NULL
   - updated_by: VARCHAR(255), NULLABLE

LOOKUP_DATA USAGE EXAMPLES:
- Policy Types: lookup_key = 'policy_type' → values: 'Health Insurance', 'Motor Insurance', 'Fire Insurance', etc.
- Status Values: lookup_key = 'status' → values: 'Active', 'Inactive', 'Pending', 'Cancelled', etc.
- Approval Status: lookup_key = 'approval_status' → values: 'Approved', 'Rejected', 'Under Review', etc.
- Configuration Status: lookup_key = 'configuration_status' → values: 'Draft', 'Published', 'Archived', etc.
- Enrollment Status: lookup_key = 'enrollment_status' → values: 'Enrolled', 'Pending', 'Declined', etc.
- Service Levels: lookup_key = 'service_level' → values: 'Basic', 'Standard', 'Premium', etc.
- Income Types: lookup_key = 'income_type' → values: 'Premium', 'Commission', 'Fee', etc.
- Document Types: lookup_key = 'document_type' → values: 'Policy Document', 'Certificate', 'Endorsement', etc.

CRITICAL LOOKUP FIELD PATTERNS:
- Any field ending with '_lid' references lookup_data.id
- Common patterns: policy_type_lid, status_lid, approval_status_lid, configuration_status_lid, etc.
- Always JOIN with lookup_data when users provide text values for enum fields
- Match user input against lookup_data.value WHERE lookup_key = '<appropriate_category>'

CRITICAL QUERY PATTERNS FOR DATA MATCHING:
- ALWAYS use PostgreSQL single quotes (') for string literals, NEVER double quotes (")
- For policy names: Use ILIKE '%pattern%' for case-insensitive pattern matching
- For opportunity names: Search in remarks, sales_pitch, and source fields using ILIKE
- When exact matches fail, always try pattern matching with wildcards
- Common policy name patterns: "Company PolicyType", "PolicyType Insurance", "Product Name Policy"
- Example: WHERE policy_name ILIKE '%Life%' OR policy_name ILIKE '%Assurance%'

SEARCH STRATEGY FOR TEXT FIELDS:
- policy_name: Direct field search with ILIKE pattern matching
- opportunity identification: Search in o.remarks, o.sales_pitch, o.source, and join with lookup_data for opportunity_type
- company identification: Search in c.name, c.contact_info fields
- Always include ORDER BY for consistent results
